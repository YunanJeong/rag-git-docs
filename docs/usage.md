# 사용 가이드

Claude Code 에서 rag-git-docs 를 쓰는 사람을 위한 문서다. 설치와 관리는 [운영 가이드](operations.md)에 있다.

## 연결하기

운영자에게 MCP서버 주소와 본인 토큰(`SERVE_TOKEN` 의 한 항목)을 받는다. 토큰을 환경변수에 두고 넘기면 명령 기록에 남지 않는다.

```bash
read -rsp "토큰: " t && echo "export GIT_DOCS_TOKEN=$t" >> ~/.bashrc && unset t    # 새 터미널부터 적용된다
claude mcp add --transport http --scope user git-docs http://<MCP서버 주소>/mcp \
  --header "Authorization: Bearer $GIT_DOCS_TOKEN"
```

Claude Code 의 `/mcp` 에 Connected 로 보이면 된다.

## 무엇을 물을 수 있나

대상 리포의 문서에 답이 있는 질문이면 된다. 따로 도구 이름을 말하지 않아도, Claude 가 필요하다고 보면 알아서 검색한다.
꼭 문서를 보게 하려면 "팀 문서 찾아보고", "git-docs 로" 처럼 한마디 붙인다.

- "○○ 서비스 배포 절차 알려줘"
- "△△ 장애 때 롤백은 어떻게 해?"
- "□□ 설정은 어떻게 잡아?"

clone 방식으로 운영 중이면 코드와 변경 이력도 물을 수 있다.

- "○○ 설정 키는 코드 어디서 읽어?"
- "이 동작은 언제, 왜 바뀌었어?"

## 어떻게 답하나

- **문서를 먼저 찾는다.** 질문과 관련된 문서 조각 몇 개를 찾아 답하고, 근거로 쓴 문서 경로와 마지막 수정일을 함께 알려 준다. 수정일이 오래된 문서면 지금과 다를 수 있다고 알린다.
- **찾지 못하면 찾지 못했다고 말한다.** 문서에 없는 내용을 지어내지 않게 해 두었다.
- **코드는 필요할 때만 본다(clone 방식).** 문서로 답이 안 되거나 코드·이력을 직접 물었을 때만, 문서 경로를 단서로 해당 리포·경로의 코드를 좁혀 읽는다. 문서로 답이 되는 질문에서는 코드를 뒤지지 않아 답이 빠르다.
- **문서와 코드는 하루 한 번 갱신된다.** 오늘 바뀐 내용은 아직 없을 수 있다.

## 연결 관리

| 하고 싶은 일 | 방법 |
|---|---|
| 토큰을 새로 받았을 때 | `~/.bashrc` 의 `GIT_DOCS_TOKEN` 을 새 값으로 고치고, `claude mcp remove git-docs` 후 위 add 명령을 다시 한다 |
| 연결 지우기 | `claude mcp remove git-docs` |
| 주소가 바뀌었을 때 | 지우고 새 주소로 다시 등록한다 |

토큰은 본인만 쓴다. 남에게 넘기지 않고, 새어 나갔으면 운영자에게 알려 새 토큰을 받는다.

## 문제 해결

| 증상 | 할 일 |
|---|---|
| 401 이 돌아온다 | 토큰이 틀렸거나 운영자가 토큰을 바꿨을 수 있다. 새 토큰을 받아 다시 등록한다 |
| 주소에 아예 접속이 안 된다 | 허용된 네트워크에서 접속했는지 확인한다. MCP서버는 허용된 IP 에서만 열린다 |
| `/mcp` 에 Connected 가 아니다 | 등록할 때 `--header` 를 빠뜨렸거나 환경변수가 비어 있을 수 있다. 새 터미널에서 다시 등록한다 |
| 답에 최근 내용이 없다 | 하루 한 번 갱신되므로 다음 갱신 뒤 다시 묻는다. 급하면 운영자에게 수집을 한 번 돌려 달라고 한다 |
| 코드를 물었는데 코드를 보지 않는다 | api 방식으로 운영 중이면 코드 도구가 없다. 운영 방식은 운영자에게 확인한다 |
