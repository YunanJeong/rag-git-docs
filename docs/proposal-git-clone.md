# 제안: 수집을 GitLab API 에서 git clone/pull 로 바꾸기

상태: **보류 중인 안건.** 결정되지 않았다. 이 문서는 새 세션에서 이 작업을 이어받기 위한 것이다.
바뀐 이유와 현재 구조는 `docs/design.md`, 쓰는 법은 `README.md` 에 있다.

## 목적

리포의 코드까지 검색에 쓰려는 것이 출발점이다. 지금은 md 만 받아 벡터 DB 에 넣는다.
코드를 볼 방법으로 두 가지를 비교했고, 그중 하나가 이 안이다.

| | GitLab API 로 그때그때 읽기 | git clone/pull 로 리포 보관 (이 안) |
|---|---|---|
| 코드 찾기 | GitLab 코드 검색 API 에 의존 | 로컬 `grep`(ripgrep) |
| 지금 구조 | 그대로. 검색 서버에 도구만 추가 | 수집을 갈아엎음 |
| 최신성 | 질문할 때 읽으니 항상 최신 | 마지막 sync 시점 (하루 한 번) |
| 디스크 | 거의 안 씀 | 리포 전체 크기만큼 |

이 안을 고르는 이유는 **코드 검색이 가장 강하고, 수집도 git 이 대신 해 줘서 오히려 단순해진다**는 것이다.

## 바뀌는 것과 남는 것

```
collect.py            바뀐다. 리포마다 clone(처음)·pull(이후), 결과로 바뀐 게 있는지 판단
collector/
├── sources/          리포 목록 받기(list_repos)만 남는다. md 목록·내용 받기는 git 이 대신한다
├── manifest.py       대부분 필요 없다. 증분·삭제를 git pull 이 해 준다
└── files.py          대부분 필요 없다
indexer/              그대로. md 파일을 읽어 색인하는 쪽이라 md 가 어디서 왔는지 모른다
serve.py              코드 찾기·읽기 도구를 여기에 추가한다
charts/, Dockerfile   볼륨 크기, git 설치, 인증 정보 정도만 바뀐다
```

### git 이 대신 해 주는 것

| 지금 직접 짠 것 | clone/pull 에서 |
|---|---|
| 해시를 비교해 바뀐 md 만 받기 (`manifest.changed`) | `git pull` 이 바뀐 것만 받는다 |
| 원본에서 지운 md 지우기 (`manifest.deleted`) | pull 하면 로컬에서도 사라진다 |
| 사라진 리포 정리 (`manifest.vanished`) | 리포 목록에 없는 clone 디렉터리를 지운다 (이건 직접 짠다) |
| 바뀐 게 없으면 색인 건너뛰기 | pull 전후 커밋 해시(`git rev-parse HEAD`)가 모든 리포에서 같으면 건너뛴다 |
| 문서별 마지막 커밋일 (API 호출) | `git log -1 --format=%cs -- <파일>` 로 추가 호출 없이 얻는다 |

## 장점

- **코드 검색이 강력하다.** 정규식, 파일 종류 거르기까지 자유롭고 빠르다. Claude Code 가 로컬 레포에서 하는 것과 같은 방식이다.
- **GitLab 코드 검색 기능에 기대지 않는다.** 리포 단위 검색 지원 여부, 그룹 전체 검색에 고급 검색이 필요하다는 제약이 없다.
- **수집 코드가 줄어든다.** 증분·삭제 판단을 git 이 하므로 `manifest.py`, `files.py` 대부분과 API 수집 코드가 사라진다.
- **날짜를 공짜로 얻는다.** 문서별 커밋일을 `git log` 로 읽으니 API 호출이 없다.
- **GitLab 부하가 적다.** 하루 한 번 pull 하고, 질문할 때는 GitLab 을 부르지 않는다.

## 단점과 위험

- **디스크.** 리포 전체 크기만큼 필요하다. 레거시나 바이너리, LFS 가 많으면 수십 GB 가 될 수 있다. `--depth 1` 이면 이력을 빼서 많이 줄지만, 그러면 문서별 커밋일을 `git log` 로 못 읽는다. 둘 중 하나를 고르거나 `--filter=blob:none` 같은 부분 clone 을 검토한다.
- **서버에 코드 사본이 남는다.** PV 와 그 백업에 사내 코드가 통째로 생긴다. 사내 정책상 괜찮은지 확인한다.
- **GitLab 의 사람별 권한을 거치지 않는다.** 검색 서버는 수집 계정 권한으로 clone 한 사본을 읽어 준다. 검색 서버 토큰만 있으면 그 계정이 볼 수 있는 모든 리포의 코드를 볼 수 있다. 파일 읽기 도구를 반복해 부르면 리포를 통째로 옮겨 적을 수도 있다. 팀원 모두가 대상 리포를 볼 수 있는 경우에만 문제가 없다.
- **시크릿이 섞일 수 있다.** 리포에 실수로 커밋된 비밀번호·키가 사본에 그대로 들어온다.
- **최신성.** 하루 한 번 pull 이라 낮에 올라온 코드는 다음 날 보인다.

## 구현할 때 알아 둘 것

- **이미지에 git 이 없다.** `Dockerfile` 이 `python:3.11-slim` 이라 git 이 안 깔려 있다. `apt-get install git` 이 필요하다. 코드 찾기에 ripgrep 을 쓰면 그것도 넣는다.
- **인증.** git 은 HTTPS 로 받을 때 GitLab 토큰을 비밀번호 자리에 넣는다. 예: `https://oauth2:<토큰>@<GitLab 주소>/<리포>.git`. 토큰이 URL 에 들어가므로 로그에 찍히지 않게 하고, clone 한 리포의 `.git/config` 에 남지 않게 한다. legacy 토큰이면 `read_repository` 스코프가 필요하다(지금은 `read_api`).
- **볼륨.** `docs` PV 용도가 "md 사본" 에서 "리포 clone" 으로 바뀐다. 크기(`persistence.docs.size`, 지금 5Gi)를 리포 전체 크기에 맞춰 늘린다. 같은 PV 를 쓰면 옛 md 사본과 `.manifest.json` 을 정리해야 한다.
- **색인 대상.** `index.py` 는 `DOCS_DIR` 아래 `*.md` 를 다 읽는다. clone 디렉터리를 `DOCS_DIR` 로 두면 그대로 동작한다. 단 `.git` 디렉터리와 `._` 로 시작하는 macOS 메타데이터 파일은 거른다.
- **청킹 경로.** 지금 조각 경로는 `<그룹>/<리포>/<리포 안 경로>` 다. clone 디렉터리도 같은 경로 구조로 두면 검색 결과 형식이 바뀌지 않는다.
- **바뀐 게 없으면 건너뛰기.** 지금은 `collect.py` 가 종료 코드 3 을 내고 CronJob 명령이 `COLLECT_EXIT` 로 `index.py` 에 넘긴다(`charts/rag-git-docs/templates/sync.yaml`). 이 약속은 그대로 지키고, 판단 근거만 manifest 비교에서 커밋 해시 비교로 바꾼다.
- **실패한 리포 보호.** pull 이 실패한 리포는 지우지 않고 옛 clone 을 그대로 둔다. 지금 API 수집이 하는 것과 같은 원칙이다.

## 코드 도구를 넣을 때

이 안을 하면 검색 서버에 코드 도구를 추가하게 된다. 토큰 과소모와 과탐색을 막으려고 처음부터 넣을 것:

- **출력 상한.** 코드 찾기는 최대 N 건과 앞뒤 몇 줄만, 파일 읽기는 한 번에 최대 수백 줄로 자른다. 넘으면 잘렸다고 알려 준다.
- **좁은 도구.** "리포 이름 + 찾을 문자열", "리포 이름 + 파일 경로 + 줄 범위" 처럼 범위를 받아야만 동작하게 만든다.
- **도구 설명에 쓰임새.** 문서 검색을 먼저 쓰고, 코드 도구는 문서로 답이 안 될 때 특정 함수나 설정 위치를 확인하는 용도라고 적는다.
- **동시 요청.** 코드 도구는 모델을 쓰지 않으니 임베딩 락과는 상관없다.

## 결정하기 전에 확인할 것

1. 대상 리포 전체 크기. GitLab 그룹 설정의 사용량 화면에서 저장소 크기 합계를 본다. 수 GB 안쪽이면 부담이 적다.
2. 사내 코드를 이 서버 PV 에 보관해도 되는지.
3. 검색 서버를 쓸 팀원이 대상 리포를 모두 볼 수 있는지.
4. `--depth 1` 로 디스크를 줄일지, 이력을 남겨 문서별 커밋일을 `git log` 로 읽을지.
